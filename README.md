# 墨栈写作台 · Mozhan Writer

> 离线优先的中文网文写作台 —— 你的稿子就是磁盘上的文件夹

**A local-first writing studio for Chinese web novels.** Your manuscript stays as plain Markdown files on your disk — no proprietary format, no database, no account lock-in.

## 为什么做这个

写给**写长篇小说**（几十万到百万字）的人。核心主张只有两条：

- **文件即数据。** 一章一个 Markdown 文件，没有私有格式、没有数据库、没有账号锁定。随时能用记事本打开、拷进 U 盘、打包带走。
- **离线优先。** 打开就是编辑器，不联网也能写完整本书。设定库、伏笔台账、一致性检查、文风分析、关系图、时间线、统计、搜索 —— **全部本机计算，0 token**。AI 只是可选的一层，不填 Key 就不出现。

## 为长篇而生的设计取舍

写长篇小说会遇到普通写作软件解决不了的问题。以下是这个项目专门处理过的：

### 85 万字规模下，重活要能在眨眼间跑完

拿一部 **6 卷 / 300 章 / 85.5 万字 + 120 条设定条目** 的书压测（`npm run scale`），
找出并修掉了三处会退化成「不可用」的写法：

| 操作 | 优化前 | 优化后 | 提升 |
|---|---|---|---|
| 关系图力导向布局 | **38.35 s** | **0.08 s** | ~480× |
| 一致性对账 | **12.03 s** | **0.31 s** | ~39× |
| 关系图构图 | 1.15 s | 0.25 s | ~4.6× |
| 条目出场索引 | 0.20 s | 0.10 s | 2× |

> 三个典型退化写法：① 力导向布局里对每条边做线性查找 —— 四万条边 × 260 次迭代 = 十亿级操作，
> 改成按下标寻址的 `Float64Array`，**算法一行没改、布局结果逐像素一致**；
> ② 笔误检测是「每章 × 每个名字 × 每个字符位置」的三层嵌套，同一章正文被重扫 120 遍；
> ③ 共现关系按「每章 × 出现条目²」建边，九成边最后被阈值滤掉 —— 换成**章节位图的按位与**。
>
> 详细分析见 [开发文档 §5.8](开发文档.md)。

关键点：**优化后行为完全一致**。`selfcheck` 里有行为对拍断言（位图算出的共现强度必须与朴素枚举逐条一致），
以及耗时预算和「规模 ×4 耗时不得超 ×10」的近线性约束。改坏了会红。

### 一致性检查全部本地算，不花 token

长篇后期最容易出的是「人设前后不一、伏笔忘回收、世界观自相矛盾」。
这个项目的检查面板**不调用任何 AI 服务**，纯规则引擎在本地跑，因此零成本、无幻觉、离线可用：

- 双链断链（推荐最接近的设定名）
- 疑似笔误（判定到只差一字，用「删一字」索引 + `hamming1` 确认）
- 伏笔超期 / 即将到期 / 信息不全 三级预警
- 角色失踪（已断 N 章没出场）
- 时序矛盾（后面某章写的时间比前面早）
- 草稿残留、未登记名词

### 同一套业务代码，跑在三个宿主上

文件系统抽象成 `FsAdapter`（`src/platform/types.ts`），**加新宿主不用改 `core/` 和 `components/` 一行**：

| 宿主 | 实现方式 |
|---|---|
| 浏览器 | File System Access API |
| 桌面 | Tauri 2（Rust IPC） |
| 安卓 | Tauri 移动端 |
| 降级 | 内存宿主（Firefox / Safari 沙盒模式） |

浏览器里的目录读写由内核保证安全，换成桌面端后这层保障没有了，所以 Rust 侧单独实现了一层
`path.rs`，配真磁盘集成测试与真 WebView2 窗口里的 42 项验收。

### AI 是可选层，产出不能直接落盘

- 支持任何 **OpenAI 兼容**服务商（DeepSeek / 智谱 / Kimi / 通义 / OpenAI / Ollama…），预置一键填充
- **AI 产出先进候选区，点「采纳」才进正文**
- 不填 API Key，整个 AI 层不渲染，写作功能一样完整
- 除 `core/ai.ts` 的 `fetch` 外，**全项目零网络调用**（`selfcheck` 有静态检查盯着）

## 功能一览

| | |
|---|---|
| **纯文件存储** | 章节是普通 `.md`，目录结构清晰可读，换任何工具都拿得走 |

| **版本快照** | 自动快照，删掉的章节也能找回 |
| **无障碍** | 界面缩放 80–160%、高对比度、三套主题 |

## 快速开始

### 下载安装

到 [Releases](../../releases) 页面下载：

- **Windows**：`..._x64-setup.exe`（约 1.6 MB，装当前用户，**不要管理员权限**）
- **安卓**：`....apk`

### 从源码运行

```bash
npm install
npm run dev          # 打开提示的 http://127.0.0.1:5173
```

需要 **Node 20+**。浏览器版推荐 **Chrome / Edge**（能直接读写本机文件夹）。

> Firefox / Safari 会自动切到「沙盒模式」，代价写在应用首页里。

### 打桌面安装包

```bash
npm run desktop:build    # 产物在 <target>/release/bundle/
```

桌面版用 **GNU 工具链**（不是 MSVC），配置与踩坑见 [开发文档 §6](开发文档.md)。

## 验收体系

**改坏了会不会被发现，答案在这几层里。**

```bash
npm run verify:all     # typecheck + selfcheck + smoke + e2e（四层）
npm run rust:verify    # 动了 Rust 才需要
npm run e2e:desktop    # 要出安装包时跑
```

| 层 | 覆盖 | 规模 |
|---|---|---|
| **typecheck** | 类型检查（`src/` 与 `scripts/` 一起查） | — |
| **selfcheck** | 核心层纯逻辑断言，内存文件系统，不联网、不要浏览器 | 420 断言 |
| **smoke** | jsdom 里把每个面板/视图挂载一遍，抓渲染期报错 | 203 断言 |
| **e2e** | 真 Chrome，真 File System Access API（挂在 OPFS 上），真键盘真鼠标 | 164 断言 |
| **e2e:desktop** | 真 WebView2 窗口 + 真磁盘 IPC | 42 断言 |

原始输出与截图存档在 [`docs/验收记录/`](docs/验收记录/)，可直接对账。

> 之所以要真浏览器这一层：File System Access API、目录句柄持久化、编辑器真渲染
> 在 jsdom 里从来没被真正跑过。补上之后确实揪出了几个只有在真浏览器里才会现形的问题。

## 技术栈

**前端** Vue 3 · TypeScript · Vite · Tiptap · Pinia
**桌面** Tauri 2（Rust）
**存储** 纯 Markdown 文件（front matter 用 YAML），zip 自研（`core/zip.ts`，不引额外依赖）

### 目录结构

```
writer-app/
├─ src/          前端源码（平台适配层 / 纯业务层 / UI）
├─ scripts/      验证脚本（自检、冒烟、规模压测、真浏览器与桌面端端到端）
├─ src-tauri/    桌面外壳（Rust：路径安全 + 文件命令 + 打包配置）
├─ docs/         验收记录
├─ 使用说明.md    面向使用者
├─ 开发文档.md    面向开发者
└─ CONTRIBUTING.md
```
