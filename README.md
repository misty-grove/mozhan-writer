# 离线写作工作台 · 实现说明

对应文档：`AI写作应用开发文档.docx`（v1.1）
实现范围：**P0（9 项）+ P1（10 项）+ P2（11 项）全部完成**，对应文档优先级表里 31 个条目已全覆盖。
离线的部分（设定库 / 双链 / 伏笔 / 去 AI 味 / 一致性 / 检索 / 记忆库 / 关系图 / 时间线 / 统计）**全部 0 token**，AI 层始终可选。

> 唯一的取舍：**语义检索没有用 embedding 模型**（要内置几十 MB 权重文件）。
> 改用本地 bigram TF-IDF + 余弦做召回 —— 对「记得零星几个词、忘了原话怎么说」有效，
> 对纯同义改写无效。这一点在搜索面板的提示里也对作者讲清楚了，不夸大。

**验收方式已经补齐**：除了核心层自检与 jsdom 面板冒烟，现在还跑**真实 Chrome 端到端验收**
（`npm run e2e`，164 项断言）。这件事的不一样之处在于 —— 之前所有验证都在 jsdom 里，
File System Access API、目录句柄持久化、编辑器真渲染这些从来没被真正跑过；
补上之后确实揪出了几个只有在真浏览器里才会现形的问题（见第七节）。

在此之外还自加了 **P3（7 项）+ P4（1 项）+ 桌面版**：真浏览器验收、首次体验、稿件导入、备份恢复、
写作体验补完、弹窗与键盘可达性、降级宿主（Firefox / Safari 也能用）、大作品规模，以及**桌面安装包**。
其中 P4 是拿「一部 300 章 / 85 万字的书」去压 —— 结果发现关系图要 38 秒、
一致性检查要 12 秒，等于不可用；现在分别是 0.08 秒和 0.31 秒（见「五·八」）。

**桌面版已经是能装的软件了**：`npm run desktop:build` 出 NSIS 安装包（1.58 MiB，装当前用户、不要管理员）
与 MSI（2.12 MiB）。它不是"再包一层壳"——文件系统本来就被抽象成 `FsAdapter`，
桌面端是第三个宿主，业务代码一行没改。代价是路径安全必须自己重做一遍（浏览器那边是内核给的），
所以 Rust 侧单独有一层 `path.rs`，还有真磁盘集成测试与真 WebView2 窗口里的 42 项验收。见「六、桌面版」。

- **`release/` 里的安装包不进版本库**（`.gitignore` 里挡着）。二进制挂 GitHub Releases，

- **`.e2e-shots/`** 是端到端验收的截图落点，每次跑都会重生成，同样不进版本库。
  以前的写法是硬编码 `F:/AI/e2e-shots` —— 一个绝对路径，别人 clone 下来必挂，已经改成工程内相对路径了。

## 一、现在怎么跑起来

```bash
npm install
npm run dev          # 打开 http://127.0.0.1:5173
```

**推荐 Edge / Chrome**（能直接读写你的文件夹）。这一步完全离线：读写的是本机真实文件夹，没有任何服务端、不联网。

> **Firefox / Safari 也能用了**（P3-F）：没有 File System Access API，就自动切到「沙盒模式」——
> 把作品文件夹导入进来写，写完导出 zip 覆盖回原文件夹。代价（不是实时同步、表达不了删除、只搬文本）
> 都写在首页和沙盒面板里。见「五·七、降级宿主」。
> 想在 Chrome 上体验这条路：`http://127.0.0.1:5173/?sandbox=1`。

> 如果某次 `npm install` 报 esbuild / rollup 本地二进制缺失，补一句即可：
> `npm i @esbuild/win32-x64-msvc @rollup/rollup-win32-x64-msvc`

### 第一次使用

1. **新建作品**：选一个父文件夹 → 填书名 → 自动生成标准目录（`大纲 / 设定 / 正文 / 记忆 / 技能`）。
2. **打开已有作品**：直接指向你已有的作品根目录；缺的目录会自动补齐，已有内容不动。
3. 左侧 `＋卷` / `＋` 建卷建章，双击标题改名，拖拽排序或跨卷移动。
   > 刚建好的作品一章都没有，这时目录会自动展开，编辑区里直接给一个「新建第一章」输入框，
   > 不用先去找 `＋`。以后想收起目录，Ctrl+B 或点左上角 `☰`。
4. 右侧 `▤`（Ctrl+J）拉出面板：卡片 / 设定 / 伏笔 / 检查 / 文风 / 统计 / 记忆 / 资料 / 搜索，**全部离线、不花 token**。
5. 想用 AI 时：设置 → AI → 填 Base URL、Key、模型 → 面板上才会出现「上下文 / 候选 / 技能」。
6. **刷新或重开浏览器会自动回到上次的作品**（目录授权仍有效时）。授权失效就退回作品列表，点一下即可。

### 快捷键

不用记：**按 `?`** 或者点工具栏右边的「?」就能看到全表（还能搜）。表本身住在
`src/core/shortcuts.ts`，派发和帮助面板读的是同一份，不会两边漂。

| 键 | 作用 |
|---|---|
| Ctrl+S | 立即保存 |
| Ctrl+B | 章节树开关（光标在正文里时这个键是**加粗**，见下面的说明） |
| Ctrl+J | 右侧资料面板开关 |
| Ctrl+F | 查找（支持正则） |
| Ctrl+P | 跳到章节筛选框 |
| Ctrl+1…5 | 写作 / 看板 / 关系图 / 时间线 / 统计 |
| Ctrl+Alt+← / → | 回到上一个 / 前进到下一个**编辑位置** |
| F11 或 Ctrl+Shift+E | 专注模式（Esc 退出） |
| Ctrl+. | 白底 / 护眼 / 夜间轮换 |
| Ctrl + / − / 0 | 界面缩放 / 复位 |
| `?` | 快捷键一览 |

**为什么有的键「在正文里会变意思」**——这是刻意设计的，不是 bug：

- 光标在正文里时，`Ctrl+B` 是**加粗**、`Ctrl+E` 是**行内代码**（编辑器原生的手感，
  硬抢会把加粗废掉）。同一条键在外面才是「目录开关 / 专注模式」。
- 判断机制是：编辑器处理过的按键会 `preventDefault`，全局派发看到
  `defaultPrevented` 就直接让位。所以不存在「按一下同时干两件事」。
- 顺带修掉了一个老 bug：以前 `Ctrl+B` 会**同时**加粗并收起目录。

**为什么导航历史用 Ctrl+Alt+←**——裸 `Alt+←` 在 Windows 的 Chrome/Edge 里是浏览器自己的
「后退」，网页不一定抢得回来。两套键都认（`Alt+←` 在桌面端/其它浏览器上更顺手），
但文档里推荐 `Ctrl+Alt+←`。

```
├─ 设定/.mdAI文件/…          ← 注入上下文的设定源
├─ 正文/
│  ├─ 第X卷 卷名/
│  │  ├─ 卷纲.md            ← 本卷目标/冲突/推进线/卷末钩子
│  │  ├─ 第001章 归乡.md
│  │  └─ 第002章 旧人.md
│  └─ 第003章.md            ← 未分卷也可以直接放
├─ 记忆/
│  ├─ 逐章摘要.md
│  ├─ 滚动总述.md          ← 软件生成块（<!-- writer:rolling -->）
│  ├─ 状态表.md            ← 软件生成块（<!-- writer:status -->）
│  ├─ 伏笔台账.md
│  ├─ 时间线.md            ← 软件生成块（<!-- writer:timeline -->）
│  └─ 文风基线.md          ← 文风指纹，可直接改
├─ 技能/技能名/SKILL.md      ← 本作品专属技能，覆盖全局同名技能
```

```markdown
settings: [仙舟联盟]
emotion: 平淡 → 压抑
updated: 2026-10-07 21:40:03
---

正文……
```

**把软件卸了，用记事本打开这些文件照样写得动。**

### 设计要点（对应文档的硬约束）

| 文档要求 | 实现位置 |
|---|---|
| 离线优先 | 除 AI 请求外无任何网络调用；`fetch` 只在 `core/ai.ts` 出现 |
| AI 可选 | `settings.aiEnabled()` 为真时，`RightDock` 才渲染「上下文/候选/技能」页签 |
| AI 产出不自动落盘 | 全部进 `aiState.candidates`，`CandidatePanel` 里点「采纳」才写入 |
| 上下文可视化 | `ContextPanel` 逐项勾选，实时显示字数与估算 token，超预算红字提示 |
| 技能只注入 name+description | `core/skills.ts → skillCatalog()`；正文按需拼进 system prompt |
| 脚本默认不执行 | 技能导入只处理 md/txt/yml/json 文本，不含任何执行路径 |
| SQLite 只是索引 | 浏览器宿主用内存索引 + localStorage 字数缓存；删掉不丢任何内容 |
| 文件即数据模型 | 没有任何私有导出格式 |

## 四、验收怎么跑（四层 + 桌面两层，全部可重复）

```bash
npm run typecheck        # vue-tsc，0 错误（src + scripts 一起查）
npm run selfcheck        # 核心层断言（内存文件系统，420 项）
npm run smoke            # jsdom 面板/视图渲染冒烟（203 项）
npm run e2e              # 真实 Chrome 端到端验收（164 项）★ 自动 build + 起预览服务
npm run scale            # 大作品压测：造一部 300 章 / 85 万字的书，把每个重活计时（观察用，不做断言）
npm run verify           # 前三步连跑（不需要浏览器）
npm run verify:all       # 四步全跑

npm run rust:verify      # cargo check（含 GUI）+ cargo test（纯逻辑，24 项）—— 动了 Rust 才需要
npm run desktop:verify   # 出安装包 + 在真实 WebView2 窗口里验收（42 项）—— 动了桌面端才需要
```

> 注意：正式工程位于 `F:\AI_Write_App\source\writer-app`，**四层可以原地全跑**
> （`jsdom` 已经进了 `devDependencies`，不用再同步到别处去）。
> `e2e` 需要本机有 Chrome；`desktop:verify` 需要 Rust 工具链，见「六、桌面版」。

> `tsconfig.json` 的 `include` 原来只圈了 `src/`，也就是**脚本层从来没被类型检查过**。
> P4 把它补上了（`scripts/**/*.ts` + 三个 test 配置），第一次跑就揪出 5 个一直躺着的
> 类型错误（参数漏了新增的 `recallTop`、可选字段没兜底、`reactive({x: false})` 被推成
> 字面量类型 `false`）。测试脚本是安全网，安全网自己漏了洞就白搭了。

**`npm run e2e` 是怎么做到真浏览器验收的**

`scripts/e2e/` 下是一个零依赖的 CDP 驱动（Node 22 自带 WebSocket/fetch，不引 Playwright）：

1. 用 `--no-sandbox --headless=new --remote-debugging-port` 拉起本机 Chrome；
   > 本机沙箱里 Chrome 自带沙箱会拒绝访问自己的可执行文件（`拒绝访问。 (0x5)`），
   > 所以必须带 `--no-sandbox`；找到的浏览器路径可用 `WRITER_CHROME` 覆盖。
2. 注入脚本把 `showDirectoryPicker()` 接到 **OPFS**（`navigator.storage.getDirectory()`）上 ——
   目录选择器是原生弹窗、自动化点不了，但 OPFS 返回的是**货真价实的 `FileSystemDirectoryHandle`**，
   于是 `getDirectoryHandle / createWritable / values() / removeEntry`、以及**把句柄存进 IndexedDB
   再刷新读回**这些代码路径全都是真实执行的，一条都没被替换掉；
3. 走完整流程：新建作品 → 建章 → 写作 → 等自动保存 → **读磁盘校验 front matter 与正文** →
   刷新（验句柄恢复）→ Ctrl+1…5 五个视图 → 九个面板 → 查找/专注/参考 → 切章 →
   导入稿件（UTF-8 / GBK）→ 备份恢复（真下载 zip 再解回来）→ 章节树全键盘 →
   **降级沙盒（`?sandbox=1`：新建 → 写 → 导出 zip → 刷新自动恢复）** → 采集控制台与网络报错；
4. 截图与报告落在工程内的 **`.e2e-shots/`**（已 gitignore，可用 `E2E_SHOTS` 改）。
   归档下来的那批在 `docs/验收记录/`。

> 为什么不用现成的 agent-browser：它的守护进程不带 `--no-sandbox`，在本机会一直卡住不返回。

**`npm run e2e:desktop` 是同一套驱动，但附着到真窗口上**

桌面宿主是第三个实现，`e2e`（浏览器）证明不了它。所以再来一层：

1. 用 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9444` 启动刚打出来的 exe；
2. `attachBrowser()`（`scripts/e2e/cdp.mjs` 新加）连上**已经在跑的** WebView2 而不是自己拉一个；
   > 一个坑：调试端口比页面先就绪，`/json/list` 先给一个 `about:blank` 空壳。
   > 附着到它上面再 reload，出来的是空白页 —— 报错却是「等待 Vue 挂载超时」，能查半天。
   > 现在要轮询到 `tauri.localhost` 那个目标才附着。
3. **不去驱动原生目录选择器**：`fs_*` 命令的 `root` 本来就是绝对路径，
   直接拿一个中文名的临时目录当作品根，把整条命令面打一遍 ——
   8 种越界写法（`..` / 盘符 / 保留名 / 结尾空格…）、BOM、幂等删除、整库另存为、
   `.wrtmp` 不留渣、隐藏目录不出现、启动期零报错；
4. 最后发一次 `plugin:window|close`，要求**进程自己退出**（守卫生效、且没把关窗弄坏）。
   唯一没被覆盖的是 `fs_pick_dir` 自己 —— 它只是 `blocking_pick_folder` 的一层包装。

**核心层自检**用**内存文件系统**模拟宿主，跑通闭环并断言结果，不联网、不需要浏览器：

- 主题：三个主题必须覆盖根上的**每一个**变量（漏一个就是一块白斑）、

## 五·三、导入已有稿件怎么用

作者大多不是从空白文档开始写的。手上已经有一份几十万字的 txt 时，走顶栏「**导入稿件**」：

1. **选文件**（`.txt` / `.md`）。也支持把 `全稿.txt` 直接拖进作品文件夹，再从「或从作品根目录里已有的文件导入」里点它。
2. **看编码**。自动判定 UTF-8 / UTF-8 BOM / UTF-16 / GBK / GB18030 / BIG5；
   判定方式不是「宽松解码看能不能读」，而是**先用严格模式试 UTF-8，失败才退到 GB 系** ——
   否则 GBK 中文会被静默解成一堆 `�`，作者只看到满屏乱码却查不出原因。
   真出现替换符会直接在界面上报出来。
3. **看分章**。默认按「第X章 / 第X节 / 第X回 / Chapter N / Markdown 标题 / （一）」这类标题行切。
   切不动就**整篇作一章**并明确告知，不硬凑出一堆莫名其妙的章。切法可换：
   按空行分段、整篇一章、或自己填一个标题正则。
   第一个标题之前的引子（书名、作者、序言）不会被丢掉，会并进第一章。
4. **预览勾选**，不想要的章取消勾选即可；可以指定导入到一个新卷（如「旧稿」）。
5. **导入**。写进 `正文/`，按「草稿」入库，**已有章节一个都不会动** —— 导入只做追加。

> 章号会按目标目录里已有的最大值往后接（卷内独立计数），所以不会和你正在写的新章节撞号。

## 五·四、备份、恢复与存储

入口：**设置 → 通用 → 备份与存储…**（三个页签）

| 页签 | 能干什么 |
|---|---|
| **导出备份** | 把整个作品打成一个**标准 zip**：解开就是原来那套目录，换台机器解压出来直接能打开。正文用 deflate 压缩（纯文本能压掉一大半），可选是否连 `.snapshots` 一起打包。条目名声明了 UTF-8 标志位，Windows 资源管理器解出来不会变成乱码目录名。 |
| **从备份恢复** | 选 zip → 先**预览**（备份来自哪本书、多少文件、多少字）→ 选「覆盖」或「跳过同名」→ 恢复。**只覆盖同名文件，包里没有的文件一律保留**，不会清空你现在的作品。`../`、绝对路径、盘符这类越界条目直接拒绝。 |
| **磁盘占用** | 按目录列出文件数与体积（正文 / 设定 / 大纲 / 记忆 / 技能 / 插件），单列出快照占了多少；顺手可调**自动快照保留份数**与**最小间隔**。 |

> 另一种备份方式：**设置 → 通用 → 整个作品复制到文件夹…**，直接拷一份目录（含快照），适合丢进网盘同步。
> 两种都行：zip 适合「带走/发送」，目录拷贝适合「持续同步」。

**关于 zip 为什么是自己写的**：整个应用只有 EPUB 导出和整库备份两处需要它，加起来不到 200 行。
写一律 store 或 deflate；读同时支持这两种 —— 因为你的备份很可能被 7-Zip / 资源管理器重新打包过，
必须还能读回来。解压用各平台自带的 `DecompressionStream('deflate-raw')`，零依赖。

## 五·五、写作体验（P3-D）怎么用

**① 跳走了要能退回来 —— 编辑位置导航**

「检查」跳到一处笔误、「搜索」跳到某段、顺着双链跳到别的章……跳完往往想回到刚才写的地方。
浏览器的后退管不了这种页内跳转，编辑器自己的撤销也管不了跨章跳转，所以单独做了一个历史栈。

- `Ctrl+Alt+←` / `Ctrl+Alt+→` 前后走；`Alt+←/→` 也认（桌面端更顺手，浏览器里可能被占用）。
- 工具栏左上角两个箭头按钮同样能点，鼠标悬停会告诉你要去哪：「后退到：第003章 旧梦」。
- 光标移动会实时更新**当前落点**，所以「后退再前进」是回到离开时那一段，不是只回到章首。
- 关掉作品就清空 —— 这是「作品内」的概念，不会带着上一本书的历史。

**② 不用背快捷键**

按 `?`（或点工具栏右侧的「?」，或设置 → 排版 → 打开快捷键一览）：
分组列出所有键位，顶上能搜（输「加粗」「导航」都行）。

> 表只有一份，住在 `src/core/shortcuts.ts`，派发和展示都读它。
> 自检里有一条断言会拿每条键位反过来问匹配器「这是谁」，答不上来就报错 —— 从机制上防止表和代码漂掉。

**③ 三种底色：白底 / 护眼 / 夜间**

`Ctrl+.` 轮换，或在设置 → 排版 → 背景主题里选。
主题类挂在 `<html>` 上而不是应用根节点上：这样 body 背景、滚动条、原生下拉框、浮层都会一起变，
不会出现「正文黑了、旁边还是白的」。夜间模式还声明了 `color-scheme`，系统级的表单控件也跟着走。

**④ 章节筛选：几百章也不用滚**

章节树顶部一直有个筛选框（`Ctrl+P` 直接跳进去），语法就三段，能叠着用：

| 输入 | 意思 |
|---|---|
| `归乡` | 标题（或文件名、标签）里含「归乡」 |
| `#草稿` | 只看这个状态；支持只写前一个字 `#待` → 待写 |
| `>3000` / `<1000` | 本章字数大于 3000 / 还没写到 1000 |
| `归乡 #草稿 >2000` | 三个条件是「且」的关系 |

命中的字会在标题里高亮，鼠标停在标题上有命中原因；整卷都没命中就整卷收起，少一层视觉噪音。
`Esc` 清空。认不出来的写法（比如 `#abc`）会当普通关键词处理，不会把你的输入吃掉。

**⑤ 章节目录可以全键盘操作**

焦点进左边目录（点一下列表空白处，或在筛选框里按 `↓`）之后：

| 键 | 作用 |
|---|---|
| `↑` / `↓` | 上下移动；折叠起来的卷，它下面的章走不到（不会跳进看不见的行） |
| `Home` / `End` | 到列表第一行 / 最后一行 |
| `Enter` | 打开光标所在的那一章 |
| `F2` | 就地改章名（输入框自动聚焦全选，`Esc` 放弃，回车确认后焦点回到列表） |
| `←` / `→` | 折叠 / 展开光标所在的卷 |

## 五·六、弹窗（P3-E）

**为什么不用 `window.prompt` / `window.confirm`**：三个原因，最后一个最要命。

1. 样式不可控 —— 夜间模式下弹出一个系统白框，像另一个软件。
2. 塞不下内容 —— 删除一章该说清「哪个文件、多少字、能不能找回」，原生弹窗只能给一整句话。
3. 桌面壳和部分 WebView **直接把它禁掉**。用户点了「新建章节」，什么也没发生，控制台也不报错 ——
   这是最难查的一类 bug。

所以现在统一走应用内弹窗：

- `confirm` 换成一个能列「影响清单」的对话框，破坏性操作的按钮是红底「删除」而不是「确定」，
  且默认焦点就在确定上（回车即确认）。
- `prompt` 换成带校验的输入框：**空着不让提交**，超长会告诉你超了几个字；
  建章还会提示「留空则为第 005 章」，不用猜。
- `Esc` 取消、回车提交、点遮罩取消；焦点被困在弹窗里（`Tab` 循环），不会跑到下面的写作界面上。

调用方式跟原生几乎一样，所以老的调用点各改一行：

```ts
const t = await askText({ title: '新建章节', placeholder: '留空则为「第005章」', maxLength: 60 })
if (t === null) return            // 取消

const ok = await askConfirm({ title: `删除《${ch.title}》`, detail: [ch.file], danger: true })
if (!ok) return
```

> 有个坑值得记：请求是**排队**的，不是「只保留最后一个」。
> 如果一次异步流程里连开两个确认框，后者挤掉前者的话，前一个 `await` 会永远挂着 ——
> 表现出来就是「点了一次删除，什么都没发生」。冒烟里有一条专门盯这个。

## 五·七、降级宿主：Firefox / Safari 怎么用（P3-F）

File System Access API 只有 Chrome / Edge 系有。以前 Firefox / Safari 打开只会看到一句
「请用 Edge / Chrome」——**这是把浏览器的账算在作者头上**。现在改成一条能走通的路：

```
导入作品文件夹 → 在内存里照常写（自动保存 / 双链 / 统计 / 快照都在）
             → 导出 zip → 解压覆盖回原文件夹
```

入口就在首页（检测不到 FSA 时自动切换，不需要手动选）：

| 入口 | 干什么 |
|---|---|
| **导入作品文件夹** | 走 `<input webkitdirectory>` 把整个文件夹读进内存（子目录、正文、大纲、记忆全进来），作品名取自你选中的那层文件夹 |
| **新建作品（沙盒）** | 没有文件夹也能开工，标准的五个目录一样不少 |
| **顶栏「沙盒 · 未导出 N」** | 实时告诉你有几个文件还只存在于浏览器里；点开是沙盒面板 |
| **沙盒面板 → 导出全部 / 仅导出改动的 N 个** | 打成 zip 落盘。全量包可直接替换原文件夹；改动包要**覆盖**到原文件夹上 |

**代价写在明面上**（首页可展开、面板里也重复一遍）：

- 磁盘不是实时同步的：不加导出，改动只在本机浏览器里。顶栏的「已保存」指的是**浏览器里**保存了。
- 压缩包表达不了「删除」：沙盒里删掉的文件，要你自己去磁盘上删（面板会把它们列出来）。
- 只搬 `.md` / `.txt` 这类文本，插图等素材留在原地方（面板里会列出「没有进沙盒的文件」）。

**为什么不是「假装支持」**：假装的结局是能力探测过了、真落盘依旧不存在，
作者写完了才发现稿子只在内存里。这里反过来 —— 宿主自称 `kind: 'memory'`，
UI 据此显示沙盒标记，代价摆在明处。

工程上的两个安排：

- **改动有兜底**：内存镜像会防抖写进 IndexedDB，刷新/崩了都还回得来（首页给「继续写」，
  或直接静默恢复）。它**不是保存**，只是防手滑；真正的落盘永远是那一次「导出」。
- **关页面前拦一下**：还有没导出的改动时走 `beforeunload`（浏览器唯一不允许自定义文案的原生弹窗）。

想在 Chrome 上看这条路长什么样（或者跑验收）：地址后面加 `?sandbox=1` 强制降级。

> 一个真实踩到的坑：进沙盒的过程中 `ensureStructure` 正在建目录，而适配层**每次写盘都会回调**过来重算差异 ——
> 那一刻工作区的 `state.ref` 还没切到沙盒根上，拿它去内存宿主里找就是「作品不存在」，
> 而且这个异常会顺着写盘路径往上冒。现在沙盒自己记住根引用，算差异失败也绝不把写盘流程带走。

## 五·八、大作品规模：一部百万字的书会发生什么（P4）

之前的验证全都在「小作品」上跑（几十章、几千字），所以有一段话一直是猜测：**「十万字规模下这点计算是毫秒级的」**。
P4 就是去把这句话量出来 —— 造一部 6 卷 / 300 章 / **85.5 万字** + 120 条设定条目的书，
对作者会真正触发的每个重活逐个计时（`npm run scale`）。

结果很难看：**有两个功能在大作品下等于不可用。**

| 操作 | 修之前 | 修之后 | 差多少 |
|---|---|---|---|
| 关系图力导向布局 | **38.35 s** | 0.08 s | ~480× |
| 一致性对账（`checkAll`） | **12.03 s** | 0.31 s | ~39× |
| 关系图构图（`buildGraph`，含章节节点） | 1.15 s | 0.25 s | ~4.6× |
| 条目出场索引（`buildRefIndex`） | 0.20 s | 0.10 s | 2× |
| 全书出场统计（`presenceStats`） | 0.19 s | 0.07 s | 2.7× |
| DOCX 整本导出 | 1.45 s | 0.98 s | （导出是一次性动作，够用） |

> 数字来自内存宿主，**不含真实磁盘 IO** —— 真实浏览器里还要再加读文件的时间，所以上表已经是下界。
> 语料是刻意凶的：120 个条目几乎每章都出现，关系图接近完全图（4 万多条边）。真人写不出这种密度，
> 但它是个合法的上界，正好用来找退化写法。

**三处退化写法（都是「换个说法就能少算几十倍」的类型）**

1. **布局里的 `live.find`**（`core/graph.ts`）
   弹簧那一圈写的是 `live.find(n => n.id === e.source)`。四万条边 × 260 次迭代 = **十亿级**的线性查找，
   而它要的只是一个「id → 下标」的映射。同一轮里还每轮 `new Map` 存受力，
   改成按 `live` 下标寻址的 `Float64Array`。算法一行没改（受力顺序、迭代次数、确定性初始位置都原样），
   所以布局结果与改之前**逐像素一致** —— 自检里的「布局结果可复现」断言原封不动地过了。

2. **笔误检测的三层嵌套**（`core/consistency.ts`）
   原来是「每章 × 每个名字 × 每个字符位置」：同一章正文被按名字个数重扫了 120 遍，
   而且每个名字都重新收一遍「长度相同的中文词」候选集。现在两件事：
   ① 每章只滑一遍窗，候选词**按名字长度分组**（长度相同的名字，候选集本来就一模一样）；
   ② 名字按「删掉第 i 个字之后长什么样」建索引 —— 两个等长的词只差一个字时，
   把那个位置从双方都删掉得到的串必然相同，所以拿候选词的「删一字」去查表就能捞出可能的名字，
   再用 `hamming1` 确认（索引只保证距离 ≤ 2）。判定口径一个字没改。

3. **共现关系是「每章 × 出现条目²」**（`core/graph.ts`）
   300 章、每章 60 个条目就是 53 万次建边，其中**九成因为共现次数不够，最后又被阈值滤掉**。
   换个角度看：两个条目的共现强度就是「各自出场章节集合」的**交集大小**。
   于是把每个条目的出场记成章节位图，两两按位与 + 数 1 —— 120 个条目只有 7140 对、每对 10 个 32 位字。

**关系图会画出四万条线，这件事得认下来**

SVG 是「一条线 = 一个 DOM 节点」，四万条边浏览器会僵住好几秒，而且那种密度图本来也看不清。
所以 `buildGraph` 现在接受 `maxEdges`（关系图视图给 1200）：**画布和布局只吃最强的这些**，
工具条上如实写「只画了最强的 1200 条（省略 N 条弱关系）」，并提示把「共现 ≥」调高。

这里有个容易写错的细节：**「完整关系」和「画出来的关系」必须分开**。
连通分量、孤立条目、枢纽排序这些统计要拿完整边集算，只砍画布 —— 否则一个只有弱关系的角色
会被误报成「跟谁都没关系」。所以 `GraphData` 同时给出 `edges`（完整，统计用）和
`drawnEdges`（≤ 上限，绘制与布局用）；不设上限时两者是同一个数组，默认行为一个字节没变。

**怎么避免再退回去**

`npm run scale` 是观察工具（只打表，不断言）。真正的闸门在 `selfcheck` 的第 41 节：

- **行为对拍**：位图算出的共现强度要与「朴素两两枚举」逐条一致；笔误检测该报的报（苏仓→苏合、白芒→白芷）、
  不该报的不报（差两个字、已知名称自身）；`maxEdges` 只砍画布不砍统计。
- **耗时预算**：120 章下对账 < 3000ms、布局 < 3000ms、构图 < 3000ms（新写法有几十倍余量，慢机器也站得住）。
- **近线性**：规模 ×4，耗时不得超过 ×10。旧写法在「布局」这一条上必红。

> 顺手修掉的两个真问题（都是这次才看见的）：
> **① 关系图的节点是普通对象**，拖动和「重排」只改 `n.x / n.y` 这两个数字，Vue 收不到通知 ——
> 表现是「圆点拖着不动、点重排没反应」，要等碰巧有别的东西触发重渲染才跳过去。现在节点包成
> `reactive`，`layout` 收 raw 对象（上万次写坐标不必逐次记账）。真实浏览器里用真鼠标事件断言了这一条。
> **② 关系图的「刷新」读不到新设定**：`ensureCodex()` 命中缓存就直接返回，所以作者在记事本里新加的
> 设定条目，切回关系图也看不见 —— 这跟「目录即数据模型」的前提直接冲突。现在这个视图强制重读。

> 另一个只有造大作品才会暴露的坑：拖动节点时 `getBoundingClientRect().width` 可能是 0
> （SVG 还没量出尺寸），原来的 `width / W` 会让 `scale = 0`，坐标直接算成 `Infinity` 飞出画布。
> 现在宽度为 0 时退回 `scale = 1`。

## 六、桌面版（Tauri）：双击就能装，装完就是一个本机软件

浏览器宿主有两个绕不过去的天花板：**用户得先有 Chrome / Edge**，而且 FSA 的目录授权冷启动时可能还要再点一次。
桌面版一次解决，同时**业务代码一行没改** —— 因为文件系统早就被抽象成了 `FsAdapter`。

### 6.1 现在有三个宿主，同一个接口

| `kind` | 文件 | 跑在哪 | 落盘方式 |
|---|---|---|---|
| `fsaccess` | `src/platform/fsAccessAdapter.ts` | Chrome / Edge | File System Access API（**内核**保证句柄出不了用户选的那个目录） |
| `tauri` | `src/platform/tauriAdapter.ts` | 桌面版（WebView2） | `invoke('fs_*')` → Rust |
| `memory` | `src/platform/memAdapter.ts` | Firefox / Safari（降级沙盒） | 内存 `Map`，手动导出 zip |

`src/platform/index.ts` 运行时挑一个。`core/` 与 `components/` 对三者完全无感 ——
`smoke` 里跑的正是 `memory` 宿主，`e2e` 里跑的是真 `fsaccess` 宿主，`selfcheck` 两边都覆盖。

### 6.2 Rust 侧为什么切成四个文件

```
src-tauri/src/
├─ path.rs          路径安全 —— 唯一的信任边界
├─ fsops.rs         纯文件操作，**不依赖 Tauri**：原子写 / 读文本（去 BOM）/ 删目录树 / 复制目录树
├─ error.rs         错误 → 一句中文
├─ commands/fs.rs   薄胶水层：10 个 #[tauri::command]
├─ lib.rs           装配 + 命令清单（唯一一份）
└─ main.rs           只有一行 writer_lib::run()
```

三条硬规矩：

1. **前端只传「根句柄 id + 相对片段数组」**，Rust 侧每个命令都过 `path::join_checked`。
   `..`、绝对路径、盘符、`\0`、控制字符、Windows 保留名（`CON`/`PRN`/`AUX`…）、
   结尾的点和空格、超过 64 层或 200 字的片段 —— 一律拒绝。绝对路径从根上就拼不出来，
   而不是「拼出来再检查」。
2. **写文件一律「临时文件 + 同目录改名」**。写到一半崩了，磁盘上要么是旧内容、要么是新内容，
   不会留下半章。上一次崩掉留下的 `.wrtmp` 会在下次写入时顺手清掉。
3. **「路径不合法」绝不静默降级成「文件不存在」**。前者是程序错了（要报），后者是正常情况（返回 `None`）。

浏览器宿主靠 FSA 的句柄天然安全，桌面端没有这层保护，所以这套校验必须在 Rust 里重做一遍。
`src-tauri/tests/fs_ops.rs` 里有一条专门试 `..\..\` 越界写入的用例。

### 6.3 为什么是 GNU 而不是 MSVC

本机没有 Visual Studio（没有 MSVC 编译器），但有 MinGW-w64 GCC 15.1，所以走 `x86_64-pc-windows-gnu`。
踩到并绕过的两个坑值得记下来，因为换台机器还会遇到：

| 坑 | 现象 | 处理 |
|---|---|---|
| `cdylib` 在 GNU 下炸 | `ld.exe: error: export ordinal too large: 94368` | `[lib] crate-type` 只留 `["rlib"]`。官方模板留 `cdylib` 是给 Android/iOS 的，桌面用不上 |
| 测试目标拿不到应用清单 | `cargo test` 一启动就 `0xC0000139`（STATUS_ENTRYPOINT_NOT_FOUND） | 应用清单只通过 `cargo:rustc-link-arg-bins` 挂给 exe，测试目标回落 comctl32 v5，缺 `SetWindowSubclass` / `TaskDialogIndirect`。修法是把 tauri 收进 `desktop` feature，`cargo test --no-default-features` 只编 `path`/`fsops`/`error`（22 项，秒级） |

### 6.4 怎么构建

```bash
npm i                       # 前端依赖（含 @tauri-apps/cli 与 @tauri-apps/api）
npm run rust:verify         # cargo check（含 GUI，约 1 分）+ cargo test（纯逻辑，24 项）

npm run desktop:dev         # 开发：起 vite + 打开 WebView2 窗口，热更新
npm run desktop:build       # 出安装包
npm run desktop:verify      # 出安装包 + 在真实窗口里验收（42 项）
```

产物在 **`<target>/release/bundle/`** 下的 `nsis/` 与 `msi/`：

| 产物 | 大小 | 说明 |
|---|---|---|
| `离线写作工作台_0.1.0_x64-setup.exe` | 1.58 MiB | NSIS，**装当前用户**（不弹 UAC）、开始菜单建「离线写作工作台」 |
| `离线写作工作台_0.1.0_x64_zh-CN.msi` | 2.12 MiB | WiX 中文 MSI |

本仓库 `release/` 里放的**就是这两个成品**（连同 `SHA256SUMS.txt` 与 `安装说明.md`）。
构建完把 `bundle/` 里的两个文件拷过去即可；`release/` 已 gitignore，不进版本库。

安装包本身是**验过的**（不是"构建成功就算"）：静默装到真机 → 拿装出来的那个 exe 再跑一遍
42 项真机验收 → 卸载。装出来的目录长这样，卸载后目录、开始菜单、注册表卸载项、进程全无残留：


### 6.6 桌面端多出来的两件事

1. **关窗保护**。自动保存是防抖的，点右上角 × 有可能把最后几秒写的字丢掉。
   `stores/workspace.ts` 挂了 `onCloseRequested`：先 `preventDefault`，`flushSave()` 落盘，再 `destroy()`。
   浏览器里没有这个钩子，退化成 `pagehide` + `visibilitychange`（尽力而为）。窗口需要
   `core:window:allow-destroy` 权限，写在 `capabilities/default.json` 里。
2. **`dragDropEnabled: false`**。Tauri 默认接管拖放，会把 HTML5 的 `dragstart` / `drop` 吃掉，
   而章节目录排序和看板拖拽全靠它。不关掉就是「拖不动，还不报错」。
3. **`withGlobalTauri: false`**。前端不在全局挂 `window.__TAURI__`，
   靠 `await import('@tauri-apps/api/core')` 动态引入 —— 这样浏览器和 jsdom 里那包根本不会被加载。

### 6.7 安卓版：为什么不能只跑一句 `tauri android build`

```bash
source F:/AI_Write_App/toolchain/env.sh
python scripts/android/build.py --release       # 签名包 → release/android/
python scripts/android/verify.py                # 静态验收（每个包 9 项）
```

脚本替 CLI 做了三件它在本机做不了的事，每件都是踩出来的：

| 坑 | 现象 | 处理 |
|---|---|---|
| **符号链接摆不出 .so** | CLI 退出码 **0**，但 `jniLibs/<abi>/libwriter_lib.so` 是 **0 字节**。APK 能装、能开图标，然后立刻闪退 | 脚本改成**复制**，并把「退出码 0」也判废 —— 见下面两条规矩 |
| `gradlew` 连不上网 | wrapper 要去 `services.gradle.org` 下发行版，本机不通 | 用预装的 gradle（`toolchain\android\gradle\gradle-9.6.1`），并 `-x` 掉它自己的 rust 任务（那步会再跑一遍 npm+cargo，而它起的 npm.bat 拿不到 Git Bash 的 PATH） |
| 产物没签名 | gradle 只出 `*-unsigned.apk`，Android 直接报「应用未安装」 | 自己跑 `zipalign` + `apksigner`。密钥在工程里：`release\android\writer-release.jks`，**不能换** —— 换了手机就不认成同一个应用 |

第一条最阴，因为它**不报错**。所以脚本里立了两条独立的规矩：

1. **退出码不能当证据。** `staged_lib_problem()` 在 CLI 跑完之后（不管成功还是失败）
   逐个比对 `jniLibs` 里的字节数与 cargo 产物，对不上就当失败、自己重新摆一遍再打包。
2. **APK 的文件名不能当证据。** 发表前 `apk_native()` 会把每个 APK **拆开**，
   看不到 > 1 MiB 的 `libwriter_lib.so` 就跳过。
   单 ABI 构建出来的包可能叫 `app-universal-release-unsigned.apk`（名字里根本没有 ABI），
   而名字里带 ABI 标签的包照样可能是空壳 —— 两种误判方向都存在。

`verify.py` 里那条 `Rust 动态库是有内容的（不是空壳）` 是最后一道闸：它读的是 zip 条目的
**实际字节数**，不是文件名。构建脚本和验收脚本各查一遍不是重复 ——
前者负责「别发出去」，后者负责「发出去的这个是对的」。

> 还有一个只在**构建被打断**时才暴露的坑：`crate-type` 是在构建开始时临时改成
> `["rlib", "cdylib"]` 的，靠 `finally` 改回来。起初那个 `finally` 的条件是
> 「我这次有没有改过」，于是上次构建若在改回来之前被 Ctrl+C / 超时杀掉，
> 再跑一次时它「一个字没改」→ 不恢复 → **Cargo.toml 永远卡在移动端状态**，
> 桌面端就带着 `cdylib` 编（而 `cdylib` 在 Windows-GNU 下会因为导出序号溢出而链接失败）。
> 现在 `set_crate_type()` 返回的是「切完之后是不是移动端状态」——
> 恢复的责任归**这一次构建**，不归「上一次改没改」。

**真实浏览器验收揪出来的问题（都已修）**

| 问题 | 症状 | 原因 |
|---|---|---|
| **改章名吞掉未保存的正文** | 在某一章里写几段，立刻按 F2 改名 → 那几段没了 | `renameChapter` 是「读磁盘旧正文 → 写新文件 → 删旧文件」，而自动保存是防抖的：刚写的还在内存里，读磁盘读到的是旧内容。修法是动手前先 `saveNow()`。这是**数据丢失**级别的问题，只靠 jsdom 冒烟发现不了（冒烟里 `state.content` 是手动赋值的） |
| 改章名时 OPFS 抛 `NoModificationAllowedError` | 改名的瞬间控制台报 `removeEntry` 失败 | 同一个「写新 + 删旧」流程撞上自动保存的尾巴，旧文件上还挂着没关干净的写入流。适配层的 `remove` 现在会等一拍重试一次，并且对「本来就不存在」当成成功（幂等） |
| F2 改名后敲字没反应 | 按完 F2 输入框出来了，但打字没进框 | 改名框是 `v-if` 现渲的，`autofocus` 属性对动态插入的元素不生效。改成显式 `focus()` + 全选；回车确认后把焦点还给列表，好接着用方向键 |
| 弹窗一打开就飘红字 | 新建章节的对话框刚打开就显示「不能为空」，像已经填错了 | 打开时立刻跑了一次校验。错误仍要实时算（它决定「确定」的禁用态），但**显示**要等用户打过字或点过确定（`touched`） |
| `Ctrl+B` 双重动作 | 光标在正文里按 Ctrl+B，既加粗又收起章节目录 | 编辑器（ProseMirror）已经在键位那一层处理并 `preventDefault` 了，但全局监听挂在 `window` 上、又不看 `defaultPrevented`，于是同一个键被处理两遍。现在全局派发先看 `e.defaultPrevented`，编辑器处理过的一律让位 |
| 切章串内容 / 打开作品编辑区空白 | 切到第 2 章还显示第 1 章正文；重开后当前章是空的 | `selectChapter` 先设 `currentId` 再异步读正文，编辑器 `watch(currentId)` 在正文到位前就拿到了**上一章的旧值**。改成先读正文再切 id；冒烟里补了 4 项 store 层断言 |
| 新作品是一片空白 | 目录默认收起、没有可见入口建第一章，用户卡住 | `openWork` 里判断「一部章都没有」就自动展开目录；编辑区加「新建第一章」输入框（不依赖原生 `prompt`，它在跨源 iframe / 部分 WebView 里会被拦） |
| 刷新总是掉回首页 | 目录句柄确实存进了 IndexedDB，但没人用它 | 补 `restoreLastWork()`：启动时若 `queryPermission === 'granted'` 就静默恢复；需要授权的（要用户手势）留在首页点选 |
| 「最近的作品」永远显示 0 字 | 新作品看起来像丢了稿子 | 原先只在打开那一刻记一次字数，改成每次保存后同步 |
| favicon 404 | 无头/离线环境都刷一条报错 | `index.html` 加内联 SVG 图标，零请求 |
| 沙盒镜像根本没存进 IndexedDB | 沙盒里写的稿子，一刷新就回到首页，什么都没了，控制台一声不响 | `put` 进去的数据里带着 Vue 的响应式代理（`sandbox.skipped` 是 reactive 数组），结构化克隆直接抛 `DataCloneError`，而这个异常被 `catch` 吞掉了。现在入库前先过一次 JSON 去代理，并且**把「镜像存没存下」显示在面板上** —— 静默失败比失败更糟 |
| 进沙盒时算差异会打断写盘 | 导入作品时直接报「沙盒作品已不存在」，条件概率极低但必现于有作品打开的场景 | 适配层每次写盘都回调重算「未导出」，而 `ensureStructure` 建目录那一刻工作区的 `state.ref` 还没切到沙盒根上 —— 拿它去内存宿主里找必然扑空，异常顺着写盘路径往上冒。现在沙盒自己记根引用，且算差异失败绝不带走写盘流程 |
| **关系图的节点拖不动、「重排」点了没反应** | 拖动圆点不跟手；换位置后画面不动，直到碰巧点了别的按钮才跳过去 | 节点是 `buildGraph` 现造的**普通对象**，拖动只改 `n.x / n.y` 这两个数字 —— Vue 的响应式根本没盯这两个字段，改完不会重渲染。修法是把节点包成 `reactive`（`layout` 收 raw 对象，上万次写坐标不必逐次记账）。jsdom 冒烟原来只断言「点了节点弹关系」，所以三年都没露头；现在加了「拖动后 transform 必须变」，并在真实浏览器里用真鼠标事件再验一遍 |
| 关系图的「刷新」读不到刚加的设定 | 在记事本里新建一个设定条目，切回关系图 / 点「刷新」都看不见它 | `ensureCodex()` 命中缓存（`loaded && refId 相同`）就直接 return。这跟「目录即数据模型、作者可以用记事本写」的前提直接冲突。现在这个视图强制重读设定库（`ensureCodex(true)`），与「设定」面板的行为一致 |
| 拖动节点把圆点甩到画布外 | 拖一下节点就消失在视野外（坐标变成 `Infinity`） | `const scale = svg.getBoundingClientRect().width / W` —— SVG 还没量出尺寸时宽度是 0，`scale = 0` 做除数。现在宽度为 0 时退回 `scale = 1` |
| 大作品下关系图打不开、检查点不动 | 85 万字的书：关系图要 38 秒、一致性检查要 12 秒 | 三处退化写法，见「五·八」：布局里的 `live.find`（十亿级线性查找）、笔误检测的三层嵌套（同一章按名字个数重扫 120 遍）、共现关系按「每章 × 条目²」建边（九成随后被阈值滤掉）。分别换成下标寻址 + `Float64Array`、滑窗 + 删字签名索引、章节位图求交 |
| 脚本层从来没过类型检查 | `scripts/` 里的类型错误一直没人知道 | `tsconfig.json` 的 `include` 只圈了 `src/`，于是 3 个测试脚本、1 个压测脚本、3 个 vite 测试配置全在检查范围之外。补上之后第一次跑就冒出 5 个错误（参数漏了后来新增的 `recallTop`、可选字段没兜底、`reactive({x: false})` 被推成字面量类型 `false`）。测试是安全网，安全网自己漏了洞就白搭 |

**桌面端真机验收揪出来的问题（都已修）**

这一轮的价值不在「构建成功」——**真正值钱的是：桌面宿主是第三个实现，它和前两个不一致的地方平时完全看不见。**

| 问题 | 症状 | 原因 |
|---|---|---|
| **`大纲/.mdAI文件/` 被藏起来** | 桌面上那三个默认大纲文件（剧情大纲 / 分卷大纲 / 人物大纲）在资料面板里看不到，**备份也带不走它们** | 隐藏规则被「简化」成「凡是 `.` 开头就藏」。可 `.mdAI文件` 是正经**内容**目录（`core/context.ts` 要读它、README 的数据模型里有它），点开头只是作者的排版习惯。而且 `listDir` 一藏，备份的 `collectFiles` 就跟着少收三个文件 —— 丢内容且全程静默。现在三个宿主共用 `platform/types.ts` 一份显式名单（`.snapshots` / `.git` / `*.wrtmp`），自检里加了两条闸门盯着它，Rust 侧也有一条同名回归测试 |
| **关窗可能静默丢稿** | 保存失败（盘满 / 文件被占）时窗口照关，那一段就没了 | `flushSave()` 失败时**返回 `false` 而不抛异常**（`saveNow` 把异常收进了返回值），守卫第一版写成 `await flushSave()` 就直接 `destroy()` —— 等于根本没看结果。现在检查返回值，失败就弹「有内容没能写进磁盘」，让作者选「丢弃并关闭」还是「留在这里」 |
| 窗口可能关不掉 | 守卫里任何一步抛异常，`destroy()` 就到不了 —— 比丢稿更糟 | `destroy()` 挪到最后且自带 `.catch`，`flushSave()` 用 try 包住。能拦住关窗的只剩作者自己点「留在这里」这一条路 |
| 调试端口连上了却报「Vue 没挂载」 | 验收脚本超时，看着像应用启动失败 | 端口比页面先就绪：`/json/list` 先给出一个 `about:blank` 空壳，附着到它上面再 reload，出来的当然是空白页。现在要轮询到真正的页面目标（`tauri.localhost`）才附着 |
| `plugin:window\|close` 被静默拒绝 | 发关闭请求毫无反应 | `core:window:default` **只有只读权限**，`close` 与 `destroy` 都得显式授。能力清单补了 `core:window:allow-close`（`destroy` 本来就有 —— 守卫要它） |
| 前端构建在 F 盘必挂 | `[vite:define] remove F:\...\esbuild-<hash>: Access is denied.` | esbuild 处理大文件时会把输入落成临时文件、读完再删；在 F 盘上这一步必失败（E 盘全通过，两块盘都是 NTFS 固定盘）。构建临时目录因此挪到 E 盘 —— 临时文件不是缓存，同样不占 C 盘 |

**还没做 / 已知边界**

- ~~**Tauri 骨架未编译**~~ → **桌面版已完成并打包**：Rust 侧 10 个命令全部编译通过、
  纯逻辑层 23 项测试通过，`npm run desktop:build` 出 NSIS + MSI。
  见「六、桌面版」。剩下的只有「未在真机 WebView 窗口里点一遍」这条 ——
  现有验收里 `e2e` 跑的是真 Chrome，桌面窗口那层还没有等价物。
- **语义检索是 TF-IDF，不是 embedding** —— 纯同义改写（换了词的同一件事）召回不到，
  那需要 embedding 模型，与「离线即装即用、体积小」的取向冲突。
  桌面端可以走本机 Ollama 桥接，接口在 `core/retrieve.ts`，换实现不动调用方。
- ~~建卷/建章用原生 `prompt`~~ → **P3-E 已全部换成应用内弹窗**（8 处 `prompt`/`confirm` 清零），
  见「五·六、弹窗」。剩下的原生弹窗只有 `beforeunload`（浏览器不允许自定义）。
- 浏览器的 `Alt+←/→` 是它自己的「后退/前进」，网页未必抢得回来（Windows 的 Chrome/Edge 尤其）。
  所以导航历史的**推荐键是 `Ctrl+Alt+←/→`**；桌面端（Tauri）用 `Alt+←/→` 更顺手，两套都认。
- ~~Firefox / Safari 不支持 FSA，只在首页给一句提示~~ → **P3-F 已改成降级沙盒**（导入 → 写 → 导出），
  见「五·七、降级宿主」。仍有的边界写在那一节：磁盘不是实时同步、压缩包表达不了删除、
  只搬文本文件 —— 这三条是 zip + 浏览器沙箱的固有约束，不是没做。
  真要「像本地文件一样实时」，那条路是桌面端（Tauri）或 Chrome / Edge。
- **关系图一次最多画 1200 条线**（上限在 `GraphView` 里的 `EDGE_BUDGET`）。
  这是 SVG 的固有成本，不是没做：密度图本来也读不出来，工具条会如实告诉你省了多少条。
  真要看完整关系，把「共现 ≥」调高，或到「统计」面板看结构健康度。
- 笔误检测只认「长度相同、恰好差一个字」，**不认增删一个字**（那是编辑距离 1 的另一种情形），
  也不做中文分词 —— 换来的好处是不引任何词表、纯本地、毫秒级。它是个提示，不是判决。

## 八、想加功能的话，往哪儿加

这一节是给后来的维护者（包括三个月后的我）看的。**先记住四条不许破的约定**，剩下的随便加：

| 约定 | 为什么不能破 |
|---|---|
| **目录即数据模型**，不引入任何私有格式 | 作者用记事本能改、十年后还能打开，是这个项目存在的理由 |
| 软件往「记忆/」写的东西一律包在 `<!-- writer:xxx -->` … `<!-- /writer:xxx -->` 之间 | 重复写入幂等；作者手写的内容永远不会被覆盖 |
| AI 产出一律先进候选区，点「采纳」才落盘 | 全自动落盘等于把稿子的控制权交给模型 |
| 除 `core/ai.ts` 的 `fetch` 外，零网络调用 | 「离线优先」不是口号，是验收项（`selfcheck` 里有静态检查盯着） |

### 8.1 加一个新视图（像看板 / 关系图 / 时间线那样）

1. `src/core/xxx.ts` —— 纯计算，输入是已经读出来的数据，输出是可渲染的结构。**不要在这里碰 DOM、不要 `fetch`**。
2. `src/views/XxxView.vue` —— 只负责画和交互。
3. 在 `src/stores/editorState.ts` 的 `view` 联合类型里加一个值，顺手在 `Ctrl+1…5` 那串派发里排个号。

`core/` 那一层被 `selfcheck` 直接跑（用内存文件系统当宿主），所以**逻辑写在这里就等于自动被测试覆盖**；
写在 `.vue` 里就只能靠 `smoke` 的渲染冒烟，覆盖度差一个量级。

### 8.2 加一个新宿主（比如未来的 Obsidian 插件、平板上跑）

只需要实现 `src/platform/types.ts` 里的 `FsAdapter`（`kind` 取个新值），然后在 `platform/index.ts`
的运行时选择里加一个分支。**不用改 `core/` 和 `components/` 任何一行** —— 三个已有宿主
（`fsaccess` / `tauri` / `memory`）就是这么来的。三者的隐藏文件规则、幂等删除语义、BOM 处理必须一致，
`selfcheck` 里有对拍。

### 8.3 加一条 Rust 原生命令

1. `src-tauri/src/commands/fs.rs` 里写函数，标 `#[tauri::command]`；
   **参数一律收「根句柄 id + 相对片段数组」，路径拼接必须过 `path::join_checked`**。
2. 在 `src-tauri/src/lib.rs` 的 `invoke_handler!` 里加一行 —— 那张表就是「前端能调用什么」的完整答案。
3. 前端在 `platform/tauriAdapter.ts` 里包一层。参数名按 Tauri 的规矩写 **camelCase**（Rust 侧是 snake_case，框架自动转）。
4. 纯逻辑放 `fsops.rs`，别塞进命令函数里 —— 那样才能被 `cargo test --no-default-features` 跑到。

### 8.4 加一个导出格式（像 EPUB 那样）

1. `src/core/exportXxx.ts`：输入是章节数组，输出 `Blob` 或字节数组。压缩要用 `core/zip.ts`
   （自研 zip，`store` / `deflate` 都支持，中文条目名的 UTF-8 标志位已处理）；
   要写 XML 就手写字符串，本项目不引额外依赖。
2. 在 `ExportDialog.vue` 的格式列表里加一项。
3. `selfcheck` 里补「导出 → 再解回来 → 内容一致」的往返断言（EPUB 那条就是这么写的）。

### 8.5 加一条 AI 技能

不用改代码：在 `skills/` 下建个文件夹，放 `skill.md`（带 name / description front matter）即可；
内置技能就是这么写的，界面上还支持文件夹/zip 导入。**技能里不能有可执行脚本** ——
导入只认 md/txt/yml/json 文本，这是刻意的。

### 8.6 加一条一致性检查规则

`src/core/consistency.ts` 里每条规则是独立函数，返回统一的 `Issue[]`。
注意大作品规模：85 万字的书上，任何「每章 × 每条目」的嵌套都会退化成十几秒。
现成的两个反面教材和修法写在「五·八」里（滑窗 + 删字签名索引、章节位图求交）。
`selfcheck` 第 41 节有耗时预算和「近线性」断言（规模 ×4 耗时不得超过 ×10），加规则时会自动被拦住。

### 8.7 加一条快捷键

改 `src/core/shortcuts.ts` 一份数据就行 —— 派发和「?」帮助面板读的是同一份，
从此不会再出现「代码一套、文档一套」。两个坑：全局派发前要先看 `e.defaultPrevented`
（编辑器处理过的键要让位），`Ctrl+字母` 别和浏览器抢（`Ctrl+P` 是打印、`Ctrl+W` 是关标签页）。

### 8.8 每加一样东西，跑一遍

```bash
npm run verify:all     # typecheck + selfcheck + smoke + e2e（真 Chrome）
npm run rust:verify    # 动了 Rust 才需要
```
