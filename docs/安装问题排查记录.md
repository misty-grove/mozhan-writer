## 一、结论速览

| 问题 | 真实原因 | 状态 |
|---|---|---|
| MSI 报「错误 1925 / 1603」 | Tauri 的 WiX 配置**默认按机器安装（perMachine）**，需要管理员提权 | ✅ 已解决（见 §四） |
| NSIS（setup.exe）静默安装返回**退出码 2** | NSIS 脚本在**已存在安装记录**时会走重装流程并 `Abort`；全新状态可正常安装 | ✅ 已解决（清干净状态即可） |
| 双击后「没有任何反应」/ 一直卡着 | **Windows「打开文件 - 安全警告」对话框在等待点击**（未签名文件的默认行为） | ✅ 已明确（点「运行」即可） |
| 从受沙箱约束的工作目录内启动安装器会卡死 | **DSH 会话工作区有沙箱约束**，从该目录启动的子进程受影响；换到工作区外即正常 | ⚠️ 环境特性，非安装包问题 |

**核心事实：安装包本身是好的。** 实测从工作区外的目录安装，退出码 0，程序正常启动。

## 三、NSIS 退出码 2 的真实含义

`installer.nsi`（构建产物，位于 `<target>/release/nsis/x64/installer.nsi`）里 `.onInit` **本身没有 `Abort`**。
所有 `Abort` 集中在：重装选择页、卸载流程、WebView2 失败分支、以及「静默 + 降级被禁用」分支。

关键代码（`Section EarlyChecks`）：

```nsis
; Abort silent installer if downgrades is disabled
!if "${ALLOWDOWNGRADES}" == "false"
${If} ${Silent}
  ${If} $R0 = -1          ; -1 = 检测到降级
    ...
    Abort
  ${EndIf}
${EndIf}
!endif
```

配合 NSIS 在**检测到已有安装**时的重装流程，在静默模式下会直接 `Abort`
—— 这就是「退出码 2」的来源。

**实测对照（同一文件、同一启动方式、同一状态，只改位置）：**

| 场景 | 退出码 | 结果 |
|---|---|---|
| 全新状态 + 工作区外的目录 | **0** | ✅ 安装成功 |
| 机器上已有安装记录 | **2** | ❌ Abort |

→ **清理干净安装状态后，安装包可正常安装。**

## 四、MSI 的 perMachine 问题

`tauri.conf.json` 里 WiX 没有（也**不支持**）`installMode` 字段
—— 核对 `node_modules/@tauri-apps/cli/config.schema.json` 的 `WixConfig` 属性表，
其中并**没有** `installMode`。生成的 `main.wxs` 硬编码：

```xml
<Package ... InstallScope="perMachine" />
<Directory Id="$(var.PlatformProgramFilesFolder)" Name="PFiles">
```

因此 **Tauri 产出的 MSI 永远是 perMachine**，标准权限下必报 1925。

**两种解法（均已实测通过）：**

1. **运行时绕过**（不改包）：
   ```cmd
   msiexec /i 包.msi ALLUSERS=2 MSIINSTALLPERUSER=1
   ```
2. **改包**（需重新打包）：在生成的 `main.wxs` 上打三处补丁，再跑 `candle` + `light`：
   - `InstallScope="perMachine"` → `"perUser"`
   - `"ProgramFiles64Folder"` / `"ProgramFilesFolder"` → `"LocalAppDataFolder"`
   - 主程序组件与 `WebView2Loader.dll` 组件：去掉 `<File KeyPath="yes">`，
     改挂一个 HKCU 注册表值作 KeyPath（否则 light 报 **ICE38**）

   自动化脚本见 `F:\AI_Write_App\toolchain\make-peruser-msi.py`。

> **注意**：当前 `bundle.targets` 为 `["nsis"]`，只产 NSIS 一种安装包。
> NSIS 版本已配置 `installMode: currentUser`，装到 `%LOCALAPPDATA%`，**免管理员**，
> 且自带 `uninstall.exe`。**推荐直接用 NSIS 安装包。**

## 五、便携版与安装版的一致性

**Tauri 在打包时会给 exe 写入 3 字节的「打包类型标记」**（构建日志中的
`Patching ... with bundle type information: nsis`），并且**打包完成后把磁盘上的文件改回 UNK**。

实测差异（同一构建、同一代码）：

| 文件 | 偏移 0x2F8BAB | 含义 |
|---|---|---|
| 磁盘上的构建产物 | `55 4E 4B` | `UNK`（未知） |
| 安装包安装出来的 | `4E 53 53` | `NSS`（NSIS） |

除此之外**整个文件逐字节相同**（3829248 字节，仅 1 处 3 字节差异）。

**因此要做「安装内容 == 便携版」的严格一致，便携版必须取自安装后的文件，而不是构建目录里的那份。**

正确做法：

```powershell
# 先正常安装一次，然后
Copy-Item "$env:LOCALAPPDATA\离线写作工作台\offline-novel-writer.exe" "<release>\便携版\" -Force
Copy-Item "$env:LOCALAPPDATA\离线写作工作台\WebView2Loader.dll"        "<release>\便携版\" -Force
# 再重打 zip 与 SHA256SUMS.txt
```

已验证：安装版 == 便携版目录 == zip 内文件（三次 SHA256 全等）。

## 六、环境注意事项

1. **不要在受沙箱约束的工作目录里直接运行安装器**（至少在本机的 DSH 会话下线时）。
   实测从工作区内启动会卡死或 Abort，从工作区外的普通目录（桌面等）启动则退出码 0。
   该目录受 DSH 会话工作区的沙箱约束影响，与安装包无关。
   （原工程目录 `E:\Worksplace\write_formation\` 已于 2026-10-09 清理，工程现位于
   `F:\AI_Write_App\source\writer-app`。）
2. **首次运行**若弹出「Windows 已保护你的电脑」或「打开文件 - 安全警告」，
   点「更多信息 → 仍要运行」或「运行」。程序未做代码签名，这是默认行为。
3. **安装前先清干净旧状态**，否则 NSIS 会走重装流程：
   ```powershell
   & "$env:LOCALAPPDATA\离线写作工作台\uninstall.exe" /S
   Remove-Item "$env:LOCALAPPDATA\离线写作工作台" -Recurse -Force
   Remove-Item 'HKCU:\Software\writerbench' -Recurse -Force
   ```
