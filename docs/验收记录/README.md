## 这些是快照，不是标准

**判断有没有通过，跑命令为准**，不要拿这里的数字当验收标准 ——
每加一个功能项数都会涨，而且它们本来就是"当时那台机器、那个版本"的记录。

```bash
npm run verify:all        # typecheck + selfcheck + smoke + e2e（四层，缺一不可）
npm run rust:verify       # 动了 Rust 才需要
npm run e2e:desktop       # 要出安装包时跑（会自己找 release 产物）
```

截图默认写到**工程内的 `.e2e-shots/`**（已在 `.gitignore` 里），
想换位置就设环境变量 `E2E_SHOTS=<目录>`。

## 四层验收分别管什么

- **typecheck** — 类型对不对（`src/` 与 `scripts/` 一起查）
- **selfcheck** — 核心层的纯逻辑断言，宿主是内存文件系统，不联网、不要浏览器
- **smoke** — jsdom 里把每个面板/视图挂载一遍，抓渲染期报错
- **e2e** — 真 Chrome，真 File System Access API（挂在 OPFS 上），真键盘真鼠标

桌面版另起一层 `e2e:desktop`，因为换了宿主（文件操作从浏览器 API 换成 IPC → Rust），
四件事只有真窗口能证伪：应用在 WebView2 里起不起得来、IPC 参数名对不对、
Rust 路径校验在真磁盘上是否生效、**关窗守卫会不会把关窗本身弄坏**。

这四层加上 `rust:test`，就是"改坏了会不会被发现"的全部答案。

## 最新一轮（2026-10-12）：打通 `e2e:desktop`

这条链路先前一直被**误判**成"本会话环境跑不通"，于是每轮都跳过。这次做了系统排查，
结论相反：**应用一直是好的，只差一个启动参数。**

**真凶**：WebView2 自带的 **Chromium 沙箱**在受限会话里初始化不了，浏览器进程起来
3~5 秒后自杀。症状极具误导性 —— 调试端口先是"连得上但不应答"，再变成"拒绝连接"，
报出来完全像"应用挂不起来"。修法是给 `--no-sandbox`（和浏览器端 e2e 给真 Chrome
加 `--no-sandbox` 是同一类问题）。加完之后端口稳定在线，页面一直停在 `http://tauri.localhost/`。

排查中被推翻的两个假设（**别再往这两条路上走**）：

1. ~~用户数据目录落在低完整性卷上~~ —— `icacls` 查过 E:/F: 两个候选目录都没有
   Low Mandatory Level 标签；换 E 盘、换 F 盘、换默认 profile 三种位置**全都一样死**；
   而不带任何 `WEBVIEW2_*` 变量启动时窗口标题正确、撑满 40 秒不退出。跟目录位置无关。
2. ~~会话沙箱限制~~ —— 沙箱内与沙箱外表现完全一致。

**顺带修掉一个真问题：本机地址会被系统代理劫走。** 作者开着 Clash 时环境变量里有
`HTTP_PROXY`，reqwest 默认认它，于是连本地模型端点（`http://127.0.0.1:11434`）
也被塞进代理，直接失败，界面上看着像软件坏了。现在规矩是 **远程地址照用代理，
本机地址一律直连**（`src-tauri/src/netutil.rs`）。这条同时也是产品行为，
不是单纯为了跑通验收。

本轮新增闸门：selfcheck §62（6 条，已反证），守的就是 `--no-sandbox` 和上面这条代理规则 ——
因为它们都是"**脚本自己**会悄悄退化"的坑，退化后从结果上根本看不出是脚本坏了。
